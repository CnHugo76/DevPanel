## 阶段 2：托管规则

实现：独立持久化 ProjectPolicy 与 ServiceHold，默认停止后暂停、CLI 强停不允许；规则写入与解除暂停仅接受 ui。锁定优先于越过参数，拒绝在入队及停止优先之前判断，并在出队执行前复核，防止界面停止与 CLI 启动竞态绕过暂停。成功越过暂停的操作记录 overrideHold；关闭停止后暂停清空全部暂停；删除服务清理锁与暂停，同时以配置修改者写 unlock/release 动态。注册、更新与校验不从项目配置读取规则。

CLI 增加只读 policy、start/restart --override-hold，status JSON 含锁定与暂停；终态失败目标全部为 POLICY_DENIED 才返回 12，部分成功但仅此类失败也返回 12，混合失败保持 6/1，未终态为 8。mock 同步规则、拒绝、来源字段与种子；删除运行中项目被拒时不提前删除动态和规则。

原生采用项目 ⋯ 菜单进入的独立“AI 权限”sheet，与编辑配置分开保存。服务行及检查器显示暂停与“允许 AI 启动”，行内锁图标和右键菜单提供锁定/解锁。旧 daemon 可选字段兼容不崩溃，强停规则按开放枚举解码。阶段 6 截图驱动：隔离 --snapshot --policy-project <id> 内联显示同一 PolicySheet，--activity-expand 展开动态配置差异；不创建新的产品页面。
