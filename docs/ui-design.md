# DevPanel 界面设计 v0.1

> 依据：`docs/product-design-v0.1.md`（产品范围以它为准）。视觉参考稿：`docs/ui-mockup.html`（静态，可在浏览器打开，顶部可切换场景）。
> 数据字段全部来自 `contract/api.md` 与 `packages/contract`；界面不得显示契约里没有的“事实”。

## 1. 形态与技术

| 项 | 决定 |
| --- | --- |
| UI 技术 | React 19 + TypeScript + Vite，位于 `apps/ui` |
| 运行形态 | 第一阶段：由管理服务在 `http://127.0.0.1:<port>/` 提供静态页面，`devpanel open` 用一次性登录码在默认浏览器打开。第二阶段：`apps/mac-shell` 用 Swift + WKWebView 包一个原生窗口，复用同一页面 |
| 开发联调 | `tools/mock-daemon` 按契约模拟管理服务（含模拟进程、日志、资源），Vite 代理 `/api` 到 mock 或真实 daemon |
| 主题 | 跟随系统浅色 / 深色；系统字体；日志使用 `ui-monospace, SF Mono, Menlo` 12px |
| 窗口 | 默认 1200×760，最小 900×560 |

## 2. 信息架构

```
┌──────────────┬──────────────────────────────────────────────────────┐
│ DevPanel  [+]│ 项目标题区：名称 · 路径 · 聚合状态      [启动][停止][重启][⚙][⋯] │
│              ├──────────────────────────────────────────────────────┤
│ ● order-svc  │ 资源摘要：CPU 132.4% · 内存 1.21 GiB (RSS估算) · 7 进程 · 2秒前 │
│   运行 2/2   ├──────────────────────────────────────────────────────┤
│ ◐ web-admin  │ 服务区（仅多服务时出现）                                  │
│   启动中 0/1 │  状态   服务   CPU    内存     运行时长   操作              │
│ ○ ml-api     │  ●运行中 后端  128%   1.02GiB  1h12m     ■ ↻              │
│   未启动     │  ●运行中 前端  4.4%   190MiB   1h12m     ■ ↻              │
│              ├──────────────────────────────────────────────────────┤
│              │ 日志区工具栏：[后端|前端] [当前运行▾] [🔍搜索] [跟随] [换行] [复制] │
│              │ 日志正文（占据剩余全部高度，等宽）                         │
│              │ …                                                     │
│ ● 管理服务已连接│ 底部状态：已加载 12,304 行 · 较早内容已按上限截断           │
```

只有一个主场景：选项目 → 看运行情况 → 操作。没有欢迎页、仪表盘、聊天框、文件树、独立监控页。

## 3. 状态视觉语言

状态永远是“图标 + 文字”，颜色只是辅助。正常运行时无动画；仅“启动中 / 停止中”允许图标做一次性的轻微脉动（`prefers-reduced-motion` 时关闭）。

| 契约状态 `ServiceState` | 图标 | 文字 | 色调 |
| --- | --- | --- | --- |
| `idle` | ○ 空心圆 | 未启动 | 中性灰 |
| `starting` | ◔ | 启动中 | 蓝 |
| `running` | ● 实心圆 | 运行中 | 绿 |
| `stopping` | ◑ | 停止中（Ns） | 琥珀 |
| `stopping` + `stopTimedOut` | ◑ | 尚未停止 | 琥珀加深，附「强制停止」 |
| `stopped` | ■ | 已停止 | 中性灰 |
| `exited` | ■ | 已退出（code） | 中性灰 |
| `failed` | ▲ | 异常 · 原因摘要 | 红 |
| `unknown` | ? 虚线圆 | 状态未知 | 紫灰 |

项目聚合 `ProjectAggregate`：`running` 运行中 n/n · `partial` 部分运行 n/m · `transition` 处理中 · `failed` 异常 · `stopped` / `idle` 已停止 / 未启动 · `unknown` 状态未知。

禁止出现的文案：健康、就绪、验证通过、正常（指业务）。`exited` 且 code 为 0 时只写“已退出（0）”。

## 4. 左侧项目列表（宽 248px，可拖拽 200–360）

- 顶部：应用名 + 「＋ 添加项目」。
- 列表项两行：
  - 第一行：状态图标 + 项目名 + 右侧运行数徽标 `2/2`。
  - 第二行（次要色）：运行时为 `运行中 · 4.1% · 812 MiB`；未运行为状态文字 + 路径尾部（`~/Project/foo`）。
  - 重名项目：名字后附灰色的父目录名 `order-svc (github/)`，悬停显示完整路径。
- 排序：按注册时间，状态变化不重新排序；支持 ↑↓ 键移动选中。点击只切换查看对象，不触发任何操作。
- 底部固定：管理服务连接状态。
  - 已连接：`● 管理服务已连接`，点击弹出小卡片：版本、PID、运行时长、管理服务自身 CPU/内存。
  - 断开：`⚠ 管理服务连接中断 · 正在重连`，同时全局进入“过期”模式（见 §9）。

## 5. 项目工作区

### 5.1 标题区

- 项目名（17px 半粗）+ 聚合状态徽标；下一行等宽小字路径，点击复制。
- 右侧按钮：`▶ 启动` `■ 停止` `↻ 重启` `⚙ 配置` `⋯`
  - 启动：存在未运行服务时可用；只启动未运行的服务。
  - 停止：存在 `starting/running/stopping` 服务时可用；停止同时会取消未完成的启动 / 重启（契约保证）。
  - 重启：存在运行中服务时可用。
  - `⋯` 菜单：复制项目 ID、复制 Agent 规则、查看配置 JSON、移除项目（运行中时置灰并写明原因）。
- 单服务项目：服务行合并进标题区，即标题区按钮直接作用于该服务，标题区下方不再出现服务表。
- 操作结果：按钮点击后进入 pending（按钮内显示小号进度，不阻塞其他操作），完成后在标题区下方出现一条可关闭的结果条，内容来自 `Operation.results`，逐服务列出，例如：`部分运行：后端 已启动 · 前端 失败：命令不存在 npm（PATH 中未找到）`。

### 5.2 资源摘要条

`CPU 132.4%  ·  内存 1.21 GiB（RSS 估算）  ·  7 个进程  ·  采样于 2 秒前`

- CPU 不截断到 100%；悬停说明“100% = 一个逻辑 CPU 满载”。
- 内存悬停说明“受管进程 RSS 之和，含共享页，可能高估”。
- `status = sampling` → `采样中…`；`partial` → 数值后加 `部分`标签并悬停写原因；`unavailable` → `不可用`，绝不显示 0。
- 采样时间超过 3 个周期未更新 → 数值变灰并显示 `已过期 · 12:03:41`。
- 单服务项目在此条加上：运行时长、运行 ID（短）、PID。
- 无服务运行时整条显示 `未运行 · 无资源数据`。

### 5.3 服务表（≥2 个服务时出现）

| 列 | 内容 |
| --- | --- |
| 状态 | 图标 + 文字 |
| 服务 | 名称；下方灰字显示附加提示：`配置已修改 · 下次启动生效`、`退出（1）· 10:42` |
| CPU / 内存 | 同 5.2 口径与缺失值规则 |
| 运行时长 | 当前运行开始至今 |
| 操作 | 行内图标按钮 ▶ / ■ / ↻；停止超时时替换为红色「强制停止」 |

- 点击行 = 选中该服务查看日志（与日志工具栏的服务分段控件双向同步）。
- 首次进入选第一个服务，之后记住每个项目上次查看的服务（localStorage）。
- 停止超时：状态列 `尚未停止（已等待 10 秒）`，操作列 `强制停止`，点击后二次确认：“将向本次运行的 3 个受管进程发送 SIGKILL，可能丢失未保存的数据。”

### 5.4 日志区

工具栏（从左到右）：
1. 服务分段控件（多服务时）。
2. 运行选择下拉：`当前运行 · 10:42 起`，其余为 `上一次 · 10:12–10:40 · 已停止`，最多 3 条（契约 `runsKeptPerService`）。查看旧运行时正文顶部有横幅：“正在查看历史运行，不再追加新日志 · 回到当前运行”。
3. 搜索框（⌘F 聚焦）：高亮全部匹配，`3 / 27`，↑↓ / Enter 跳转；占位文字“搜索已加载的日志”。
4. 开关：`跟随`、`自动换行`。
5. `复制`：有选区时复制选区，否则复制“已加载的全部”（附行数提示）。

正文：
- 虚拟滚动；每行等宽；行号不显示，悬停行左侧显示时间戳（`ts`）。
- `stream = err`：行左 2px 红色竖条；`stream = sys`（管理服务插入的说明，如“已启动 PID 4182”“发送 SIGTERM”“进程已退出 code=0”）：斜体次要色，前缀 `devpanel ›`。
- 支持 ANSI SGR 颜色/粗体/下划线；其他控制序列丢弃；内容一律按文本渲染。
- 重启后自动切到新运行，旧运行与新运行之间不混排。

跟随行为：
- 默认跟随到底。用户向上滚动即自动关闭跟随；新日志到达时在底部浮出 `↓ 12 条新日志 · 跳到最新`，不改变滚动位置。
- 跟随关闭不影响后台采集。

底部状态行：
- `已加载 12,304 行` / `较早内容已按上限截断（每次运行 32 MiB）` / `采集中断：…`（契约 `gap` 事件）/ `暂无新输出 · 最后输出于 3 分钟前`。

空状态：
- 服务从未运行：“该服务尚未运行。点击「启动」后，日志会显示在这里。注册项目不会自动启动。”
- 运行中但无输出：“暂无输出。部分程序会缓冲输出，日志可能延迟出现。”

## 6. 添加 / 编辑项目（右侧抽屉，宽 560px）

结构与 `ProjectConfig` 一一对应，UI 能编辑的字段 CLI 都能提交，反之亦然。顶部两个标签：`表单` / `JSON`（同一数据，切换时互相转换，JSON 无效时禁止切回表单并标出错误位置）。

表单：
- 项目名称（必填）、根目录（必填，绝对路径；第二阶段原生壳提供“选择…”）。
- 服务卡片列表，可折叠、可用 ↑↓ 调整顺序（顺序 = 项目级启动顺序）：
  - 名称（必填）、ID（必填，小写 slug，新建时由名称生成；已有运行记录后修改需确认）。
  - 工作目录（相对根目录，默认 `.`）。
  - 启动命令：单行输入，按 shell 规则拆分，下方实时预览 argv：`["mvn", "spring-boot:run"]`。勾选 `通过 Shell 运行` 时保存为 `["/bin/zsh", "-lc", "<原文>"]` 并在预览中写明。检测到 `&`、`nohup`、`-d`（docker compose）时给出黄色警告：“请使用前台运行方式，后台化的进程无法被管理”。
  - 高级（折叠）：环境变量表（名称 / 值 / 🔒 敏感），名称含 TOKEN、SECRET、PASSWORD、KEY 时默认勾选敏感；已保存的敏感值显示“已设置（留空则保持不变）”，不提供“显示明文”；停止等待秒数（默认 10）。
- 「＋ 添加服务」。
- 校验：失焦时调用 `POST /api/v1/config/validate`，在字段下方显示 `issues`；每个服务卡片底部显示解析结果：`将执行 /opt/homebrew/bin/mvn · 目录存在`，或红字 `在 PATH 中找不到 mvn`。
- 底部：运行中编辑时显示提示“保存后在下次启动时生效，不会自动重启”。按钮：`取消` `保存`。不提供“保存并启动”。
- 冲突：保存返回 `REVISION_MISMATCH` → 抽屉顶部提示“配置已被其他客户端（可能是 AI）修改”，提供 `载入最新配置`（丢弃本地修改前二次确认）。注册返回 `CONFIG_CONFLICT`（同根目录已存在）→ 提示并提供“打开已有项目”。

## 7. 其他对话框

- 移除项目：确认框写明“只从面板移除配置和日志，不会删除 <root> 下任何文件”。运行中时禁止并提示先停止。
- Agent 规则：等宽文本框展示产品文档 §11.3 规则，`<项目ID>` 已替换为真实 ID；按钮 `复制`。
- 首次打开且无项目：主区居中空状态——“还没有项目。在你的编程 Agent 里说「把当前项目加入 DevPanel」，或手动添加。” 下面放一段可复制的 CLI 说明和「添加项目」按钮。

## 8. 交互细节

- 所有变更请求都带 `X-DevPanel-Client: ui`；按钮在请求进行中防重复点击，但并发正确性由后端保证。
- 异步响应（日志页、日志流、操作结果）必须核对 `projectId / serviceId / runId`，与当前查看对象不一致则丢弃，杜绝串日志。
- 只订阅当前查看运行的日志流；切换服务 / 运行时关闭旧流。
- 快捷键：⌘F 搜索、⌘C 复制选区、↑↓ 项目列表、Esc 关闭抽屉 / 搜索。
- 时间显示用本地时区；运行时长 `1h12m` / `3m05s`。
- 字节显示 `MiB / GiB`，保留 1–2 位小数。

## 9. 断连与过期

- 事件流断开或超过 25 秒未收到 `ping`：
  - 侧栏底部变为告警，主区顶部出现黄条“与管理服务的连接中断，下面显示的是 12:03:41 的状态，可能已过期”。
  - 所有状态图标叠加“过期”灰度；资源值变灰；启动 / 停止 / 重启按钮置灰并提示原因。
  - 指数退避重连（1s→2s→5s→10s 封顶）；重连成功后用 `snapshot` 全量替换本地状态，日志流从最后的 `seq` 续接。
- 启动时连不上：主区显示“无法连接 DevPanel 管理服务”，给出 `devpanel daemon start` 命令（可复制），不渲染任何项目状态。

## 10. 不做

菜单栏图标、托盘、系统通知、跨服务合并日志、日志导出、资源趋势图、拖拽排序项目、多窗口、主题自定义。
