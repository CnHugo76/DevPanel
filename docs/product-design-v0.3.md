## 1. 本版目标

| 问题 | v0.3 的回答 |
| --- | --- |
| 为了 clean / install / package 打开整个 IDEA | **Maven 视图**：模块树、生命周期阶段、Profiles、常用开关，双击运行，输出在 DevPanel 里 |
| 一些固定组合（`clean install -DskipTests -pl backend -am`、`pnpm build`）每次要手敲 | **快捷操作**：AI 按项目定义，一键执行 |
| 看改了哪些文件、提交、临时存一下改动，要开 IDE 的提交面板 | **Git**：改动文件列表 → 打开单个文件的差异窗口 → 暂存、提交、储藏 |

三者都属于**项目**，不属于某个服务。因此检查器从“只显示服务”扩展为“服务或项目”。

## 2. Maven 视图

### 2.1 对标对象
IntelliJ IDEA 的 Maven 工具窗口的**基础部分**。面向懂 Maven 的使用者，直接使用 Maven 的概念（模块、阶段、Profile、`-pl`、`-am`），不做翻译。

### 2.2 内容
- **模块树**：从项目根的 `pom.xml` 开始，按 `<modules>` 递归展开；每个模块显示 `artifactId`（有 `<name>` 时附名称）、打包类型。父 POM 未在本地出现时照样显示，只标注“父 POM 不在项目内”。
- **Lifecycle**：每个模块下列出标准阶段 `clean`、`validate`、`compile`、`test`、`package`、`verify`、`install`、`site`、`deploy`。
- **Profiles**：汇总所有模块中声明的 Profile，复选框勾选后作为 `-P` 传入（三态：默认 / 强制启用 / 强制禁用 `!id`）。
- **工具栏开关**：跳过测试（`-DskipTests`）、离线（`-o`）、对选中模块“同时构建依赖模块”（`-am`）。
- **运行方式**：双击阶段运行；在同一模块内多选阶段（例如 clean + install）合成一条命令，按生命周期顺序排列；也可以在“运行 Maven 目标…”中手输目标（例如 `dependency:tree`、`versions:display-dependency-updates`）。
- **执行命令**：项目根有 `mvnw` 时默认使用它，否则使用 PATH 中的 `mvn`（可在项目设置中切换）；在项目根执行，对子模块使用 `-pl <模块路径>`（这样 `-am` 才有意义，也能使用根目录的 `.mvn/` 配置），Profile、开关按勾选附加。环境变量（如 `JAVA_HOME`）沿用项目级配置。
- **输出**：与服务日志相同的视图（ANSI、搜索、跟随、堆栈折叠），显示最终退出码与用时；可以取消、强制取消。

### 2.3 模型从哪里来
- 管理服务**静态解析** `pom.xml`（`<modules>`、`<groupId>/<artifactId>/<name>/<packaging>`、`<profiles>`），不运行 Maven、不访问网络、不读取 `~/.m2`。
- 解析结果按 `pom.xml` 的修改时间缓存；界面提供“重新加载”。
- 解析失败的模块在树中标红并显示原因，不影响其他模块。

### 2.4 快捷操作（AI 定义）
- AI 在注册 / 更新项目时登记若干快捷操作：名称、命令（argv，可引用 `${key}` 选项）、工作目录、可选说明、可选“服务运行时需确认”。它们**不限于 Maven**（例如 `pnpm build`、`./gradlew test`、数据库迁移脚本）。
- 快捷操作显示在项目卡片的“快捷操作”行和项目检查器中，一键执行；人可以编辑、删除，也可以把一次 Maven 运行“存为快捷操作”。
- AI 也可以通过 CLI 运行快捷操作或 Maven 目标，让人在 DevPanel 里看到同一份输出。

### 2.5 规则与范围
- Maven 运行与快捷操作统称 **“任务运行”**：跑到结束，退出码 0 为成功；托管方式与服务完全相同（独立进程组、pid + 启动时间核验、子进程跟踪、日志上限、资源采样）。
- 同一项目同一时刻**最多一个 Maven 运行**（同一工作区内并发构建会互相破坏 `target/`）；同一快捷操作最多一个运行；不同快捷操作可并行。
- 取消、强制取消、最长运行时间、daemon 重启核验、不自动重跑、保留最近 5 次运行、单次输出上限 16 MiB：同第 1 稿。
- 运行需确认：Maven 阶段含 `clean`，或快捷操作标注了“服务运行时需确认”，且项目有服务在运行时，先确认。
- 结束通知：窗口不在前台时通知成功 / 失败。
- **不做**：Dependencies 依赖树、依赖分析与图、Plugins 节点（插件目标需要读取本地仓库中的插件描述，留到下一版视需要再做）、Maven 设置编辑（settings.xml）、Run Configurations、Gradle 视图。

## 3. Git

### 3.1 交互顺序
1. **改动文件列表**（Git 页主体）：按“已暂存 / 未暂存 / 未跟踪 / 冲突”分组，勾选即暂存；下方是提交区和储藏。
2. **点击某个文件 → 打开差异窗口**（独立窗口，类似 IDEA 的差异查看器）：默认左右并排，可切换为统一视图；显示整个文件并高亮改动处；上一个 / 下一个改动、上一个 / 下一个文件；窗口内可以暂存 / 取消暂存当前文件。

### 3.2 范围
| 做 | 不做 |
| --- | --- |
| 当前分支、领先 / 落后远端（只读） | 切换 / 创建 / 删除分支 |
| 改动文件列表；差异窗口（并排 / 统一、整文件上下文） | 拉取、推送、抓取 |
| 暂存 / 取消暂存（文件级） | 丢弃改动、删除储藏 |
| 提交（含“修改上一次提交”） | 历史图、blame、对比任意提交、行级暂存 |
| 储藏：保存（可含未跟踪）、列表、恢复（pop / apply） | 交互式变基、合并、冲突解决 |

### 3.3 规则
同第 1 稿：仓库 = 项目根所在工作树；由管理服务调用本机 git；**写操作只由界面发起，CLI 不提供 Git 命令**；敏感文件名提交前警告；钩子照常执行并显示输出；锁冲突如实报错、不删锁文件；Git 页或 Git 摘要可见时才刷新（窗口在前台时每 5 秒），不监听文件系统；差异单文件上限 5,000 行或 2 MiB。

## 4. 界面要点（详见 ui-design-v3）
- 项目卡片：标题行有 Git 摘要；选项行下方是“快捷操作”行；有 `pom.xml` 的项目在卡片 ⋯ 与快捷操作行末尾有“Maven…”入口。
- 项目检查器标签：**Maven**（仅 Maven 项目）、**快捷操作**、**Git**、**选项**。
- 差异窗口是独立窗口，可同时开多个文件。

## 5. 验收要点
| 场景 | 必须观察到的结果 |
| --- | --- |
| 打开 Maven 项目 | 模块树与 `<modules>` 一致；Profiles 汇总；父 POM 不在项目内时有标注；不运行 Maven |
| 运行阶段 | 双击 `install`：命令为 `./mvnw -pl backend install`（按开关附加 `-am -DskipTests -o -P…`）；输出实时；结束显示退出码与用时 |
| 多选阶段 | clean + install 合成一条命令且顺序正确 |
| 并发 | 同一项目已有 Maven 运行时，再运行被拒绝并提示；快捷操作不受影响 |
| 快捷操作 | AI 登记后出现在卡片；引用选项按当前值替换；注册时不执行 |
| 取消 | 进程按身份核验后结束、无残留 |
| CLI | `devpanel maven run` / `devpanel action run` 的输出在程序中实时可见；退出码反映结果 |
| Git 列表 | 分组正确；勾选暂存后刷新；非仓库时有提示 |
| 差异窗口 | 点击文件打开；并排 / 统一切换；文件间导航；二进制与超大文件有提示 |
| 提交 / 储藏 / 敏感文件 / 钩子失败 / 锁冲突 | 同第 1 稿 |
| 资源 | Git、Maven 页不可见时不轮询、不解析；任务结束后释放采样与日志订阅 |
